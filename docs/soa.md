# Déclaration d'applicabilité (mini-SoA) — ISO/IEC 27001:2022, Annexe A

Périmètre : la plateforme Helpdesk (front, API, worker, base, stockage objet, supervision) telle que déployée par ce dépôt.
Les contrôles retenus sont ceux listés dans le sujet (section 5) ; pour chacun on indique la mesure, où la trouver
dans le dépôt, la preuve qu'elle fonctionne, et ce qui reste à faire (limites assumées).

| Contrôle | Mesure mise en place | Où dans le dépôt | Preuve | Limite / reste à faire |
|---|---|---|---|---|
| **A.8.24** Utilisation de la cryptographie | TLS sur l'Ingress (certificat signé par une AC interne) ; Secrets Kubernetes chiffrés dans etcd (AES-CBC) ; pièces jointes et exports chiffrés côté application (Fernet) avant d'arriver au stockage objet ; sauvegardes chiffrées AES-256 ; mots de passe hachés en argon2id ; AWS : KMS + RDS/S3 chiffrés | `terraform/local/cluster.tf`, `secrets.tf`, `backend/app/crypto.py`, `backup/backup.sh`, `terraform/aws/` | `etcdctl get` montre `k8s:enc:aescbc` ; octets bruts d'une sauvegarde = `Salted__` ; test `test_crypto.py` | La base PostgreSQL du lab n'est pas chiffrée au niveau disque (volume local kind) : réglé côté AWS (`storage_encrypted`). Entre pods, le trafic est en clair (pas de service mesh). |
| **A.5.15** Contrôle d'accès, **A.8.2** Droits d'accès privilégiés, **A.8.3** Restriction d'accès à l'information | RBAC Kubernetes (compte `ci-deployer` limité à son namespace, pas de lecture de Secrets), comptes de service sans jeton monté, rôles applicatifs `user/agent/admin`, un utilisateur ne voit que ses tickets, IAM AWS limité par bucket (IRSA) | `k8s/base/rbac.yaml`, `backend/app/routes_tickets.py`, `terraform/aws/data.tf` | `kubectl auth can-i` (oui/non attendus), tests `test_user_cannot_see_other_users_tickets` | Pas de SSO/OIDC. |
| **A.8.5** Authentification sécurisée | argon2id, mot de passe ≥ 10 caractères, JWT à durée limitée, blocage après 5 échecs / 5 min (Redis), message d'erreur identique pour e-mail inconnu ou mauvais mot de passe | `backend/app/security.py`, `routes_auth.py` | `test_wrong_password_then_lockout` ; HTTP 429 observé en prod | Pas de MFA. |
| **A.5.17** Informations d'authentification, **A.8.12** Prévention de la fuite de données | Aucun secret dans Git (`.gitignore`, gitleaks en CI) ; secrets générés par Terraform, injectés via Secrets Kubernetes ; `.env` local ignoré ; secrets jamais journalisés ; AWS : mot de passe RDS géré par Secrets Manager | `terraform/local/secrets.tf`, `.github/workflows/ci.yml` (job `secrets`) | Résultat gitleaks | Les secrets sont dans l'état Terraform : en vrai projet, backend distant chiffré. Pas de coffre type Vault/External Secrets. |
| **A.8.15** Journalisation | Logs JSON sur stdout (requêtes, événements de sécurité : connexions, échecs, refus d'accès, changements de rôle), collectés par Alloy vers Loki, 72 h de rétention ; journaux d'accès de l'Ingress ; AWS : audit EKS + flow logs VPC | `backend/app/logging_conf.py`, `terraform/local/platform.tf` | Panneau « Événements de sécurité » du dashboard Grafana | Rétention courte (lab) ; pas de SIEM, pas d'horodatage infalsifiable. |
| **A.8.16** Activités de surveillance | Prometheus + Alertmanager + Grafana ; 7 alertes (indisponibilité, erreurs 5xx, latence, file saturée, tâches en échec, force brute, sauvegarde manquante) | `monitoring/`, `k8s/base/monitoring.yaml` | Alerte `HelpdeskBackendDown` déclenchée lors du test de panne | Alertmanager sans destinataire (pas d'e-mail/Slack configuré). |
| **A.8.13** Sauvegarde des informations | CronJob quotidien `pg_dump` → chiffrement → bucket `backups`, rétention des 7 dernières, test de restauration dans une base séparée | `backup/`, `k8s/base/backup.yaml`, `k8s/ops/restore-job.yaml` | Logs du job, restauration : 4 utilisateurs / 8 tickets retrouvés | Sauvegarde logique quotidienne : RPO = 24 h. Le bucket de sauvegarde est dans le même cluster (copie hors site à prévoir ; AWS : versioning + Glacier). |
| **A.8.9** Gestion de la configuration | Toute l'infrastructure (cluster, réseau, secrets, supervision) décrite en Terraform ; applicatif en manifestes Kustomize versionnés ; versions de charts et d'images figées | `terraform/`, `k8s/` | `terraform plan` sans changement après application | Dérives manuelles possibles (voir rapport : quelques correctifs faits à la main avant d'être reportés dans le code). |
| **A.8.31** Séparation des environnements | Namespaces `helpdesk-dev`, `-test`, `-prod` ; secrets distincts par environnement ; quotas ; politiques réseau par namespace ; Pod Security `baseline` | `terraform/local/namespaces.tf`, `k8s/overlays/` | `kubectl get ns` ; mots de passe différents | Même cluster physique : un vrai projet séparerait au moins la prod. |
| **A.8.4** Accès au code source | Dépôt Git ; en production : branche `main` protégée, revue obligatoire, droits par équipe, déploiement prod sur tag avec validation manuelle | `.github/workflows/ci.yml` (environnement `production`) | — (réglages à faire sur la plateforme Git) | Non démontrable en local : dépend de la configuration GitHub. |
| **A.8.25** Cycle de développement sécurisé, **A.8.28** Codage sécurisé, **A.8.7** Protection contre les logiciels malveillants | Pipeline : ruff (règles bandit), tests, `pip-audit` / `npm audit`, hadolint, Trivy (images + configuration), gitleaks ; validation des entrées (Pydantic), liste blanche de types de fichiers et limite de taille, noms de fichiers assainis, images non-root et en lecture seule | `.github/workflows/ci.yml`, `backend/app/` | Sorties des scans (rapport) | Pas d'antivirus sur les fichiers téléversés (ClamAV serait l'étape suivante). |
